# Product Auto Workflow - 产品自动化开发工作流

这是一个自动化的开发工作流 Skill，引导你从需求到上线完成完整的开发流程。

## 🚀 快速开始

### 启动工作流

在 Claude Code CLI 中输入：

```
使用 product_auto_workflow skill 开始一个新功能开发
```

或者：

```
我要开发一个新功能：[描述你的功能]
请使用 product_auto_workflow 引导我完成
```

## 📋 工作流程

### 完整流程（功能开发）

```
需求澄清 → 架构设计 → 代码实现 → 测试验证 → 代码审查 → 交付上线
   ↓           ↓           ↓           ↓           ↓           ↓
 明确需求    技术方案    编写代码    质量保证    团队评审    生产部署
```

### 快速流程（Bug 修复）

```
问题定位 → 根因分析 → 修复实现 → 回归测试 → 发布修复
```

### 重构流程

```
目标识别 → 重构计划 → 测试保护 → 逐步重构 → 验证清理
```

## 🎯 Skill 功能

### 1. 自动引导
- ✅ 自动识别当前开发阶段
- ✅ 提供当前阶段的操作指南
- ✅ 自动加载对应的提示词模板
- ✅ 给出下一步行动建议

### 2. 智能提问
- ✅ 根据需求类型生成针对性问题
- ✅ 最多 3 个核心问题，避免过度询问
- ✅ 结合现有代码上下文提问

### 3. 检查清单
- ✅ 每个阶段提供完成检查清单
- ✅ 自动验证是否满足进入下一阶段的条件
- ✅ 记录完成的检查项

### 4. 知识复用
- ✅ 自动记录本次开发的关键决策
- ✅ 保存提示词模板供未来使用
- ✅ 积累最佳实践库

## 📖 使用示例

### 示例 1：添加优先级功能

**用户输入**：
```
我要给任务列表添加优先级功能
```

**Skill 自动执行**：
```
[阶段 1/6] 需求澄清
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✓ 识别到功能类型：优先级管理
✓ 加载提示词模板：prompts/requirement/priority-feature.md
✓ 分析现有代码：检测到任务管理模块

📝 需求澄清问题（3个关键问题）：

1. 【数据结构】优先级分几个等级？
   建议：3级（高/中/低）或 5级（紧急/高/中/低/无）

2. 【UI设计】优先级如何展示？
   选项：颜色标识、图标、文字标签、数字

3. 【功能范围】需要哪些关联功能？
   □ 按优先级排序
   □ 按优先级筛选
   □ 优先级快速切换

请回答这些问题，我将进入架构设计阶段 →
```

**用户回答**：
```
3个等级，用颜色区分（红/黄/灰），需要排序功能
```

**Skill 继续**：
```
[阶段 2/6] 架构设计
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✓ 需求明确度：80%
✓ 开始架构设计

📐 技术方案设计：

1. 【数据模型】
   ```javascript
   task: {
     id: string,
     title: string,
     priority: 'high' | 'medium' | 'low',  // 新增字段
     priorityColor: '#FF3B30' | '#FFCC00' | '#8E8E93'
   }
   ```

2. 【UI组件】
   - 位置：任务列表项左侧添加颜色指示条
   - 组件：PriorityIndicator (4px × 100% 高度)
   - 交互：点击切换优先级

3. 【功能实现】
   - 新增：setPriority(taskId, priority) 方法
   - 修改：任务排序逻辑，优先级高的排在前面
   - 数据迁移：现有任务默认设为 'medium'

✅ 架构设计检查清单：
□ 数据模型设计完成
□ UI组件设计完成
□ 功能逻辑设计完成
□ 考虑了数据迁移
□ 考虑了边界情况

确认设计方案后，进入代码实现阶段 →
```

### 示例 2：修复 Bug

**用户输入**：
```
日程表的编辑功能点击没反应，帮我修复
```

**Skill 自动执行**：
```
[Bug 修复流程 - 阶段 1/5] 问题定位
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✓ 识别到场景：Bug 修复
✓ 切换到快速修复流程

🔍 问题重现步骤：

1. 请提供重现步骤（或我帮你测试）
2. 预期行为是什么？
3. 实际发生了什么？
4. 是否有报错信息？

基于你的描述，我将：
→ 检查日程表相关代码
→ 查找事件监听器
→ 定位问题根因
```

## 🔧 配置选项

### 工作流偏好
```yaml
# 自动化程度
automation_level: high  # high | medium | low

# 问题数量限制
max_questions: 3        # 每个阶段最多问几个问题

# 检查清单严格性
checklist_strict: true  # 是否必须完成所有检查项才能进入下一阶段

# 知识库记录
save_learnings: true    # 是否自动保存本次开发的经验
```
