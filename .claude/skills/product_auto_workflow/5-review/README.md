# 审查员（Reviewer）

Review 开发成果，记录经验，持续优化。

## 功能说明

对完成的工作进行：
- ✅ 质量检查（需求/设计/代码）
- ✅ 找出问题和改进点
- ✅ 记录经验教训
- ✅ 自动优化模板（让下次更好）

## 使用方法

```
使用 reviewer 检查本次开发：[功能名]
```

## 自动工作流程

```
[步骤 1] 选择检查清单
  → requirement-checklist.md（需求）
  → design-checklist.md（设计）
  → code-checklist.md（代码）

[步骤 2] 逐项检查
  → 对照 doc/tel 规范
  → 检查完整性、准确性、可测试性
  → 标记通过/未通过项

[步骤 3] 生成 Review 报告
  → 问题列表
  → 改进建议
  → 评分和总结

[步骤 4] 记录经验
  → 保存到 learnings/YYYY-MM/
  → 记录：做得好的、可改进的、下次注意的

[步骤 5] 自动优化
  → 更新提示词模板（补充遗漏的问题）
  → 更新检查清单（新增检查项）
  → 让下次开发更顺畅
```

## 目录说明

### checklists/
各阶段的检查清单。

- `requirement-checklist.md` - 需求检查（10项）
- `design-checklist.md` - 设计检查（12项）
- `code-checklist.md` - 代码检查（15项）

### learnings/
按月份组织的经验记录。

格式：`YYYY-MM/[功能名]-learning.md`

#### 经验记录模板
```markdown
# [功能名] 开发经验

## 需求阶段
- ✅ 做得好：...
- ⚠️ 可改进：...
- 💡 下次注意：...

## 设计阶段
- ✅ 做得好：...
- ⚠️ 可改进：...
- 💡 下次注意：...

## 开发阶段
- ✅ 做得好：...
- ⚠️ 可改进：...
- 💡 下次注意：...

## 总结
关键决策、技术选型理由、踩过的坑...

## 自动优化建议
基于本次经验，建议更新：
- [ ] 1-requirement/prompts/XXX.md：新增问题...
- [ ] 2-architecture/patterns/XXX.md：补充说明...
- [ ] 5-review/checklists/XXX.md：新增检查项...
```
